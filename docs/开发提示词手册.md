# zcode 开发提示词手册（Proteus · 千面）

> 用法：每次新会话先说 P0 对齐上下文，之后按阶段顺序取用对应提示词。每次只派一个任务，收口必须跑测试。
> 配套上下文文件：`<REPO>\AGENTS.md`（zcode 若读 `CLAUDE.md` 等其他文件名，把本文件内容复制过去即可）。

---

## 一、通用心法（比提示词本身更重要）

1. **一次一个任务**。别把阶段一塞进一句话，agent 会贪多写烂。
2. **先读后写**。每个新会话先让它读 AGENTS.md 并复述理解，防止它自由发挥。
3. **验收标准写进提示词**。"全量 pytest 绿 + commit" 是每个任务的固定尾巴。
4. **报错贴全文**。Traceback 一行都别省，让 agent 定位根因而不是绕过。
5. **跑偏就拉回**。直接说"停一下，重读 AGENTS.md 第 2 节硬规则，检查你刚才的改动违反了哪条"。
6. **不满意的产出当场说**。"这个方案引入了 X 依赖，违反硬规则 5，换 stdlib 实现"——比事后重构便宜十倍。

## 二、P0 · 每个新会话的开场白（必发）

```text
先读 <REPO>\AGENTS.md，然后做两件事：
1. 用不超过 10 句话复述：项目目标、方案 C 的架构分层、第 2 节 8 条硬规则、阶段一验收标准；
2. 列出你当前 working directory 下能看到的项目结构。
不要写任何代码。复述完等我下一步指令。
```

作用：强制对齐 + 验证它真的读了。复述错了当场纠正，比写完再返工便宜。

## 三、阶段一 · 模式抽象（P1 → P5，按顺序发）

### P1 · Fork 内核进仓库

```text
执行阶段一的第 0 步：把 XPentest 内核 fork 进本仓库。严格按 AGENTS.md 第 3 节执行：
1. 从 <WS>\网安项目开发规划\10-pentest-agent 拷贝 penagent/、tests/、pytest.ini、requirements.txt 到本仓库根目录（排除 __pycache__、_tmp*、.pyc）；
2. 内核 README.md 拷为 docs/XPentest内核README.md；
3. .env 不拷贝：新建 .env.example（只含 PENTEST_LLM_BASE_URL / PENTEST_LLM_API_KEY / PENTEST_LLM_MODEL 三个占位键），并把 .env 写进 .gitignore；
4. git init + 首次 commit（message: 阶段一: fork XPentest 内核）；
5. 在本机 Python 3.12 环境跑 python -m pytest tests，报告通过数。全绿才算完成。
```

### P2 · ModeProfile 模型与加载器（核心）

```text
实现 ModeProfile。按 AGENTS.md 第 4 节规范：
1. 新建 penagent/modes.py：模式模型 + YAML 加载器 + inherits 单继承合并 + 字段校验；依赖约束看硬规则 5（优先 stdlib dataclass + 手写校验，确需 Pydantic 先说明理由）；
2. 新建 modes/ 目录，落盘 base.yaml、pentest-standard.yaml、ctf-web.yaml（内容照抄 AGENTS.md 第 4 节，不得改动字段语义）；
3. 新建 prompts/pentest.md 与 prompts/ctf.md 两份提示词模板：pentest 版强调证据链引用与可复现 PoC；ctf 版强调快速试错、flag 正则收口、分钟级预算；
4. PenAgent 增加 mode 参数：system prompt 按 persona 注入，registry 按 capability 过滤后生成工具 schema（被 deny 的工具根本不出现在提示词里）；
5. 测试：模式加载/继承合并/字段校验失败/deny 工具不出现在 schema，各至少 1 例；
6. 全量 pytest 绿后 commit（message: 阶段一: ModeProfile 模型与加载器）。
```

### P3 · Policy 模式驱动化（唯一需要小重构的点）

```text
把 penagent/agent.py 的 Policy 从硬编码 authorize 布尔值升级为模式驱动裁决，严格对齐 AGENTS.md 硬规则 1/2/3：
1. capability.constraints：命中约束的工具，执行前把约束参数冻结追加到 args；
2. capability.deny + permission 档位：deny 与 hard_deny 直接拒绝；require_confirm 返回"待人工确认"（沿用现有 evidence 记录 blocked 的方式，标注原因与档位）；
3. scope.target_allowlist 沿用现有 _in_scope 逻辑，模式可覆盖白名单但不可放宽默认 127.0.0.1 之外未授权的目标；
4. 保持向后兼容：不传 mode 时行为与现在完全一致；
5. 测试：constraints 冻结追加 / deny 机制性拒绝（不是提示词拒绝）/ require_confirm / 向后兼容，各至少 1 例；
6. 全量 pytest 绿后 commit（message: 阶段一: Policy 升级为模式驱动裁决）。
```

### P4 · 可插拔 Verifier（CTF 与渗透的分水岭）

```text
实现可插拔成功判定器。按 AGENTS.md 第 4 节 verifier 字段：
1. 新建 penagent/verifier.py：定义 Verifier 接口；实现 EvidenceChainVerifier（包装现有 valid_refs 反幻觉逻辑，语义不得削弱——硬规则 2）与 FlagRegexVerifier（pattern 匹配任务输出，支持 auto_retry 次数内的重试再判定）；
2. PenAgent 收口逻辑改为调用注入的 verifier：pentest-standard 挂 evidence_chain，ctf-web 挂 flag_regex；
3. 测试：flag 命中 / flag 未命中重试后命中 / 重试耗尽判失败 / 渗透模式引用伪造证据仍被拦，各至少 1 例；
4. 全量 pytest 绿后 commit（message: 阶段一: 可插拔 Verifier）。
```

### P5 · 记忆按模式分区 + 阶段一验收

```text
两步走，先实现后验收：
一、memory 按模式分区：Memory 的 missions 与 skills 读写增加 memory_namespace 维度，_rank_skills 只在当前 namespace 检索，模式间互不串库；补测试（同名技能两个 namespace 不互通）。
二、阶段一验收，按 AGENTS.md 第 5 节逐条自检并输出报告：
1. 同一内核同一目标分别用 pentest-standard 与 ctf-web 各跑一次（可用 mock/离线方式），展示两种不同的判定输出；
2. 在 ctf-web 模式下尝试调用 nuclei，证明被机制性拒绝而非提示词劝退；
3. budget.max_steps 超限时触发换策略而非直接崩溃；
4. 全量 pytest 通过数与耗时。
把验收结论写入 docs/阶段一验收报告.md 并 commit（message: 阶段一: 验收报告）。
```

## 六、救场提示词（出问题时用）

```text
# 跑偏拉回
停一下。重读 AGENTS.md 第 2 节硬规则，对照你刚才的改动说出违反了哪几条，先给纠正方案再动手。

# 报错处理（把 traceback 全文粘在下面）
完整 traceback 如下。先定位根因，说明是哪一层的错误（模式层/内核/工具），再修。禁止用 try-except 吞掉或绕过式修补。修完跑全量 pytest。

# 改动越界
你改动了 AGENTS.md 第 3 节红线之外的文件。回滚这次改动，只允许触碰本任务清单内的文件。

# 依赖越界
你引入了 X 依赖，违反硬规则 5。改用 stdlib 实现，除非你能证明 stdlib 无法完成。
```
