## 一、渗透模式实战（真 LLM + 授权靶场）

**靶标**：`examples/target.py --port 8080`（本地授权演示靶：Flask 假门户，/admin 401、/debug 信息泄漏）。

**第一跑（复现权限闸门行为）**：`outcome=failed（步骤 5）`——`pentest-standard` 权限档位 `default: ask` 在无头 CLI 下无人应答，LLM 的 4 次工具调用（http_probe / httpx_probe / port_scan / robots_fetch）**全部被闸门拦截且未执行**，随后结论因"缺少可复现证据引用"被 evidence_chain 判定器拒绝。**机制完全按设计工作**（无审批不执行、无证据不收口），但暴露 F-E2E-1（见第四节）。

**修复 F-E2E-1 后第二跑（真 LLM，12 分钟，8+ 步）**：`outcome=success`，证据引用 `seq=[1..10]`，作战记录 `data/missions/pentest-standard/ec8adcd5.json`：

```
3. port_scan 127.0.0.1 → {"open_ports":[135,445,3306,3389,8080]}
4. robots_fetch http://127.0.0.1:8080 → {"status":200,"disallow":["/admin","/debug"]}
5. http_probe /admin → 401        6. http_probe /debug → 200（65 字节）
7. httpx_probe /debug → 技术栈识别  8. ehole_finger → BaseHTTP/0.6 Python/3.12.9
【风险提示】/debug 匿名可访问是当前最值得深入的信息泄漏点…
```

侦察结论与靶标实际行为**完全一致**（/admin 受保护、/debug 泄漏、技术栈识别正确），LLM 自主选择了正确的工具序列并在收口给出下一步建议。

## 二、CTF 三题端到端解题

**通道 A：官方 scripted 评测**（`examples/eval_ctf_solve.py`，脚本化决策 + 真实工具 + 真实 FlagRegexVerifier）：

| 题目 | 结果 | 解法 | flag |
|---|---|---|---|
| simple-rsa | success（3 步） | rsactf_attack（RsaCtfTool fermat 分解相近素数） | `flag{rsa_close_primes_pwned}` |
| b64-stego | success（3 步） | file_type + codec_decode | `flag{b64_stego_found}` |
| encoding-chain | success（3 步） | file_type + codec_chain（hex→base64→rot13） | `flag{layered_encodings_ok}` |

**合计 3/3 解出。** 期间发现 F-E2E-2（见第四节）：b64-stego 原脚本依赖 python_solve，本机 Docker 守护进程闪断时被沙箱**正确拒绝**，脚本化"假收口"随即被 FlagRegexVerifier **正确驳回**（反幻觉/强验证再次生效），暴露评测脚本对 Docker 的隐性依赖，已改用免隔离的 codec 工具链。

**通道 B：真 LLM 驱动**（deepseek-v4-flash 自主选工具）：encoding-chain 题，`--mode ctf-crypto`，3 步收口，`flag{layered_encodings_ok}`，证据引用 `seq=[2]`（codec 工具真实输出），作战记录 `data/missions/ctf-crypto/5cb8eeec.json`。

## 三、RayScan / Chameleon MCP 联调

探针：`examples/mcp_e2e_probe.py`（走内核 `discover_mcp` 真实连接，非 mock）。

| Server | 传输 | 注册 | 真实调用 | 结果 |
|---|---|---|---|---|
| RayScan（`wvs/mcp_server.py`，HTTP :18000） | streamable-http | **3 工具**（scan / list_modules / get_report） | `rayscan_list_modules` | **ok=True**，返回检测模块清单 JSON |
| Chameleon（stdio，自备 .venv） | stdio | **12 工具**（scrape_url / crawl_site / map_site…） | `chameleon_scrape_url` | 首打 `127.0.0.1` 被其**自带 SSRF 防护拒绝**（组件安全策略，属预期）；改打 `https://example.com` **ok=True**，返回 Markdown 采集结果 |

**结论**：两个外部 MCP Server 在内核统一注册中心真实可用，"新增能力 = 改配置 + 注册，不改内核代码"的架构承诺实测成立。附带验证：Chameleon 的 SSRF 防护与 Proteus 的白名单/沙箱是**两层独立防线**。
