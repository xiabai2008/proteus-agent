## 〇、设计第一原则：LLM 驱动（非规则写死）

**本产品的每一个"智能"环节都由大模型驱动，规则只做三件"不智能"的事：**

| 环节 | 由谁驱动 | 说明 |
| --- | --- | --- |
| 任务理解与目标分解 | **LLM** | 分析目标特征 → 制定攻击计划 |
| 工具选择与调用决策 | **LLM**（ReAct 循环） | 读工具输出 → 决定下一步（用哪个工具/什么参数/是否换策略） |
| 利用链推理 | **LLM** | 结合 CVE/POC 情报推理利用路径 |
| 反思与归因 | **LLM** | 任务后复盘：为什么成功/失败，产出结构化经验 |
| 技能提炼 | **LLM** | 把成功过程抽象为可复用技能模板 |
| 记忆检索应用 | **LLM** | 检索相关历史经验注入上下文，指导本轮决策 |
| 策略自我迭代 | **LLM**（可选 RL 增强） | 基于失败模式改进自身 prompt/策略 |

**规则的边界（仅限）：**
- 安全护栏：授权校验、目标白名单、高危动作熔断、调用超时
- 格式解析：工具输出 → 结构化 JSON（nmap/sqlmap 等输出解析）
- 反幻觉校验：结论必须引用真实证据（08 证据链机制）
- 成本控制：token 上限、长输出先压缩再入上下文

> 一句话：**LLM 负责"想"，工具资产负责"做"，规则负责"踩刹车"。**

## 一、产品定位

**一个以 dawnforge-pentest 为内核、接入任意 LLM 大模型、整合个人全部攻防资产、具备"记忆—反思—技能沉淀—策略进化"自我进化能力的渗透测试 Agent。**

一句话：**"把你自己二十余个工具项目的经验，做成一个会越用越强的 AI 渗透工程师。"**

| 维度 | 定位 |
| --- | --- |
| 用户 | 个人（渗透学习者/竞赛/授权测试），后续可向团队扩展 |
| 形态 | CLI + MCP 服务（可被 Claude/Codex/OpenCode 等调用）+ 可选 Web |
| 内核 | 复用 dawnforge-pentest（多智能体 + 证据驱动反幻觉 + agent-agnostic + 持续记忆） |
| 核心创新 | **自我进化**：经验记忆 → 反思归因 → 技能沉淀 → 策略进化（RL 可选） |

## 三、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│  交互层  CLI  │  MCP Server（供外部 Agent 调用）  │  Web(可选)  │
├─────────────────────────────────────────────────────────────┤
│  决策层  多智能体编排（dawnforge-pentest 内核，LLM 驱动）     │
│          LLM 决策循环（ReAct / Plan-and-Execute）             │
│          侦察Agent → 扫描Agent → 利用Agent → 后渗透Agent     │
│          （每个 Agent = LLM + 工具注册表 + 记忆检索）         │
│          + 证据驱动反幻觉（结论必须引用证据）                 │
├─────────────────────────────────────────────────────────────┤
│  能力层  ToolRegistry（统一工具注册表，MCP 协议接入）        │
│          —— 纯工具执行层，无智能，由上层 LLM 调度            │
│          侦察: asset-survey/ENScan_GO/nmap/StarMap          │
│          扫描: rayscan(多引擎) / ruoyi-scan(框架专项)       │
│          情报: poxiao(CVE+POC+MCP) / Chameleon(抓取)        │
│          利用: poxiao POC / ruoyi-scan AI POC / exploit     │
│          修复: 02 修复Agent │ 固证: 08 证据链               │
├─────────────────────────────────────────────────────────────┤
│  进化层（核心创新，LLM 驱动 + 记忆/技能存储）                 │
│  作战记忆库 → LLM反思引擎 → LLM技能提炼 → 策略进化(LLM+RL)  │
├─────────────────────────────────────────────────────────────┤
│  评测层  07 Agent靶场(能力评分) │ 08 合规核验 │ 04 BAS剧本库 │
└─────────────────────────────────────────────────────────────┘
```

## 四、自我进化机制（核心设计）

### 4.1 进化闭环

```
执行渗透任务
   │
   ▼
① 作战记录（证据链 + 工具调用 + 决策日志 + 成败）
   │
   ▼
② 反思引擎（任务后复盘：成功归因 / 失败模式 / 工具调优点）
   │
   ▼
③ 经验入库（结构化：技能 / 策略 / 参数 / 盲区 / 情报）
   │
   ▼
④ 下次任务检索应用（按目标特征匹配最优技能链）
   │
   ▼
⑤ 能力量化（07 靶场跑分 → 进化效果可见）
```

### 4.2 五个进化单元（全部 LLM 驱动）

| 单元 | 机制（LLM 驱动） | 数据来源 | 复用资产 |
| --- | --- | --- | --- |
| **记忆库** | 每轮任务的结构化经验（成功链/失败链/目标指纹→技能映射），**由 LLM 总结生成** | 作战记录 + LLM 反思输出 | dawnforge 持续记忆 |
| **技能沉淀** | **LLM 把成功攻击链提炼为可复用技能**（参数化、带前置条件、带证据） | 记忆库聚类（LLM 辅助） | 04 BAS 剧本格式 |
| **反思引擎** | **LLM 复盘**：任务后分析成败归因（工具/参数/策略/情报缺失），产出改进建议 | 裁判/复盘（攻防平台 judge_agent 即 LLM） | 攻防平台裁判 + 02 评估体系 |
| **策略进化** | **LLM 自我迭代 prompt/策略**（基于失败模式改进决策指令）；可选 RL（quantum-rl-scheduler 在 07 仿真训练） | 07 靶场分数 + 反思建议 | quantum-rl-scheduler + 07 |
| **盲区发现** | **LLM 分析工具调用统计与失败聚类** → 生成"待补能力清单" | 记忆库统计 + LLM 归纳 | 各工具资产 |

### 4.3 反幻觉约束（贯穿进化）

- 技能沉淀必须携带**可复现证据**（原始命令 + 输出摘录 + 目标指纹），无证据的技能不进入库——**由 LLM 提炼、由证据链校验**
- 反思结论必须引用作战记录中的具体事件（08 证据链机制）——**LLM 写结论，证据链验证引用**
- 进化只改"策略与技能"（LLM 迭代），不改"安全边界"（授权校验、白名单、熔断只增不减——规则写死）

## 七、差异化与风险

### 差异化
1. **个人资产闭环**：rayscan+poxiao+ruoyi-scan+dawnforge 的组合是独有工具链（LLM 调度，非规则写死）
2. **LLM 驱动的自我进化**：记忆/反思/技能/策略全部由大模型驱动，且进化效果在 07 靶场跑分量化
3. **证据驱动反幻觉贯穿**：渗透结论、技能沉淀、反思结论全部可审计
4. **agent-agnostic**：Claude/Codex/OpenCode/DeepSeek 等任意 LLM 都能驱动（dawnforge 已验证），不绑死模型

### 风险与对策
| 风险 | 对策 |
| --- | --- |
| 工具多而散，集成工作量 | 统一 ToolRegistry + MCP 协议，先接 3 个核心工具 |
| LLM 决策不可控（幻觉/漂移） | 证据驱动反幻觉 + 规则只做安全护栏（授权/白名单/熔断） |
| 进化不可控（策略漂移） | LLM 迭代策略但 07 跑分做回归门禁，退化即回滚 |
| LLM 成本 | 攻防训练平台的模型路由/压缩策略复用（便宜模型做摘要，贵模型做决策） |
| 安全合规 | 授权校验 + 目标白名单 + 全动作留证（08） |
| 与 07 叙事重叠 | 07=评测基准，本品=LLM 驱动渗透产品（工具整合+进化） |
