# 沙箱降级评估 · 隔离档位的边界决策

> 日期：2026-09-19　　背景：`docs/端到端实战演练.md` F-E2E-4（本机 Docker Desktop 守护进程反复闪断）引出的问题——**容器不可用时，沙箱该不该有降级路径？**

---

## 一、三档语义（现状，`penagent/sandbox.py`）

| 档位 | 被动工具 | 需要隔离的工具（dangerous / 声明 sandbox） |
|---|---|---|
| none | 直接执行 | **拒绝**（none 档只放行白名单内被动工具） |
| local | 直接执行 | 直接执行（仍受 Policy 白名单与授权档位约束） |
| docker | 直接执行 | 容器内执行；容器不可用则**拒绝**，绝不裸跑 |

判定发生在工具执行前，由 ToolRegistry 持有策略对象保证——不是靠调用方自觉（硬规则 1/3）。容器不可用时拒绝执行而不是降级直跑，是 docker 档存在的全部意义。

## 二、评估的三个备选方案

### 备选 A：docker 不可用时静默降级为宿主直跑

**否决。** 这会让"隔离档位"的保证静默失效：模式声明 `sandbox: docker`（如 ctf-crypto 的 `python_solve` 等价宿主任意代码执行），操作者以为在容器里跑，实际在宿主跑。静默降级破坏硬规则 1 的全部意义——约束必须在执行前机制性生效且**可预期**。演练中的正面案例恰是反例：b64-stego 原路径被沙箱正确拒绝后，脚本化"假收口"被 Verifier 正确驳回（F-E2E-2）——拒绝不是故障，是保证。

### 备选 B：补 WSL2 / 子进程降级路径作为第三种隔离实现

**暂不做。** 理由：

1. **收益有限**：WSL2 隔离强度低于容器（共享宿主文件系统可配置，默认挂载 /mnt 下全部盘符），做成"第二个 docker 档"要么弱化隔离语义、要么增加第三种档位语义，复杂度上来了，威胁面（一次性解题脚本 = 任意代码执行）却没有变化。
2. **成本不低**：Windows + WSL2 的进程包装、路径映射（`D:\` ↔ `/mnt/d`）、输出编码（GBK/UTF-8）都是实打实的工程量，而当前唯一的隔离需求工具（python_solve）在 CTF 评测里已有免隔离替代路径（codec 工具链，F-E2E-2 的修复）。
3. **替代品已存在**：`local` 档就是显式的人工降级路径——模式作者明确声明 `sandbox: local` 时，隔离需求工具宿主直跑但仍过白名单/授权档位。这是**配置时的知情决策**，而不是运行时的静默降级，语义边界清晰。

### 备选 C：维持现状（拒绝而非降级，local 档为显式降级路径）

**采用。** 配套约定：

1. `sandbox: docker` 的模式在容器不可用时报明确错误（含修复指引），不崩溃、不裸跑——现状已如此，`tests/test_sandbox.py` 用例钉住。
2. 需要在无容器环境跑高隔离工具时，模式作者显式降档 `sandbox: local`，并在模式文件注释中写明降级理由与残余风险（工具仍过 PolicyGate 白名单 + 权限档位）。
3. 专用镜像缺口（F-E2E-4 关联）：`python:3.12-slim` 内无 RsaCtfTool，隔离执行的真实集成需要专用镜像或 requirements 注入——待 Docker 环境稳定后补测，`PENTEST_DOCKER_IMAGE` 环境变量（`penagent/sandbox.py`）已预留镜像切换。

## 三、结论

**"拒绝而非降级"是特性不是缺陷。** 隔离档位的可用性由模式作者在配置层显式取舍（docker / local / none），运行期不做静默退化；所有档位下工具都必须过 PolicyGate 白名单与授权档位。F-E2E-4 记录的 Docker 闪断是基础设施问题，处置方式是修环境或显式降档，而不是给内核加隐式回退。
